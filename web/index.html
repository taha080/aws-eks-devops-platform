How it works

The card above uses the live API, and stores the map in this browser when that API is unreachable. The service stores links in SQLite or PostgreSQL and answers with HTTP.

  1. 01

    Paste

    An http or https URL, up to 2048 characters. Add a custom code, or leave that field blank.

  2. 02

    Mint

    Blank codes are 7 characters, letters and digits. Probe and docs names are reserved, same as the API.

  3. 03

    Keep

    The live API stores the link. If it is unreachable, this page writes localStorage instead.

  4. 04

    Follow

    Open the short link. On the API that is a 302. In this browser it is #/code, then a redirect.

On AWS

Architecture

Terraform builds the account. GitHub Actions ships the image. Helm runs FastAPI on EKS. The nodes sit in private subnets.

Ship the image

  1. GitHub Actions CI/CD

    Pull requests run lint, tests, the image build, Terraform, Helm, and scans. Deploy is manual.

  2. Docker

    Multi-stage image, non-root user, the same Dockerfile CI builds.

  3. ECR

    The registry the private nodes pull from.

  4. Helm

    Upgrades the release in the linkforge namespace.

Modules under infra/. Dev is a small cluster. Prod is three zones and Multi-AZ RDS.

IRSA

Pods read the RDS secret from Secrets Manager with an IAM role. The password stays out of the image, the chart, and the workflow log.

Dev and prod

Dev is one replica and a SQLite file. Prod is PostgreSQL, two or more replicas, an HPA, and a PodDisruptionBudget. Helm will not render extra replicas on SQLite.

Pipelines

CI does not assume a cloud role. The AWS deploy workflow is manual and skips itself when secrets are missing. This page is a third workflow, and it only uploads web/.
